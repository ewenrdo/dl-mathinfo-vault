    On s'intéresse au groupe $(\mathrm{Aut}(\mathbb{Z}/8\mathbb{Z}), \circ)$ des automorphismes du groupe $(\mathbb{Z}/8\mathbb{Z}, +)$.

            \item Pour tout $a \in \mathbb{Z}$, on définit l'application
            \[

            \]
            Montrer que $\mathrm{Aut}(\mathbb{Z}/8\mathbb{Z}) = \{\phi_a \mid \bar{a} \text{ générateur de } \mathbb{Z}/8\mathbb{Z}\}$.
            \item Quel est son ordre ?
        \end{enumerate}
        \item Montrer que tous les éléments de $\mathrm{Aut}(\mathbb{Z}/8\mathbb{Z})$ autres que l'identité sont d'ordre 2.
        \item À quel groupe $\mathrm{Aut}(\mathbb{Z}/8\mathbb{Z})$ est-il isomorphe ?
    \end{enumerate}
}

\exercise{2}{Produit de deux sous-groupes et application dans $\mathcal{S}_6$}{
    \begin{enumerate}
        \item Soit $G$ un groupe et soient $K$ et $H$ deux sous-groupes de $G$. On suppose que :
        \[
        \forall (h, k) \in H \times K, \quad hk = kh \quad (*)
        \]
        \begin{enumerate}
            \item Montrer que le sous-ensemble $HK$ de $G$ constitué des éléments de la forme $hk$ avec $h \in H$ et $k \in K$ est un sous-groupe de $G$.
            \item Soit $D$ l'ensemble des éléments de $H \times K$ de la forme $(g, g^{-1})$ où $g \in H \cap K$. Montrer que $D$ est un sous-groupe distingué de $H \times K$.
            \item Construire un isomorphisme de groupes entre $(H \times K)/D$ et $HK$.
        \end{enumerate}
        \item Application : on se place dans le groupe symétrique $\mathcal{S}_6$ et on considère les deux sous-groupes $H = \langle (12), (34) \rangle$ et $K = \langle (12), (56) \rangle$.
        \begin{enumerate}
            \item Montrer que $H$ et $K$ sont deux groupes abéliens d'ordre 4 et qu'ils vérifient l'hypothèse $(*)$.
            \item En utilisant la question 1.(c) calculer l'ordre de $HK$.
            \item Donner un système complet de représentants de $(H \times K)/D$.
        \end{enumerate}
    \end{enumerate}
}

\exercise{1}{Arbres binaires à deux couleurs}{
    On considère les arbres binaires « à deux couleurs » représentés en OCaml à l'aide du type suivant :
    \begin{quote}
    \texttt{type br\_tree = Nil | B of br\_tree * br\_tree | R of br\_tree * br\_tree}
    \end{quote}

    \begin{enumerate}
        \item Écrire la fonction \texttt{count\_B : br\_tree -> int} qui compte les nœuds internes étiquetés par \texttt{B}.\\
        Par exemple \texttt{count\_B (B (R (Nil, B (Nil, Nil)), Nil))} vaut \texttt{2}.

        \item Écrire la fonction \texttt{all\_R : br\_tree -> bool} qui vérifie si tous les nœuds internes sont étiquetés par \texttt{R}.\\
        Par exemple \texttt{all\_R (R (R (Nil, R (Nil, Nil)), Nil))} vaut \texttt{true}.

        \item On dit qu'une valeur de type \texttt{br\_tree} est \textit{correcte} si sur chaque chemin de la racine à une feuille il y a autant de \texttt{B} que de \texttt{R}. Par exemple \texttt{B (R (Nil, Nil), R (B (Nil, Nil), B (Nil, Nil)), Nil))} est correcte, et \texttt{B (Nil, R (Nil, Nil))} ne l'est pas.\\
        Écrire la fonction \texttt{is\_correct : br\_tree -> bool} qui vérifie si un arbre est correct.

        \item On considère l'itérateur suivant :
        \begin{quote}
        \texttt{let rec fold\_br fNil fB fR t =}\\
        \texttt{\phantom{XX}match t with}\\
        \texttt{\phantom{XX}| Nil -> fNil}\\
        \texttt{\phantom{XX}| B (l,r) -> fB (fold\_br fNil fB fR l) (fold\_br fNil fB fR r)}\\
        \texttt{\phantom{XX}| R (l,r) -> fR (fold\_br fNil fB fR l) (fold\_br fNil fB fR r)}
        \end{quote}
        de type
        \begin{quote}
        \texttt{'a -> ('a -> 'a -> 'a) -> ('a -> 'a -> 'a) -> br\_tree -> 'a}
        \end{quote}
        Redéfinir les fonctions des points 1 et 2 en utilisant \texttt{fold\_br}.

        \item On considère la fonction suivante, de type \texttt{br\_tree -> int list} :
        \begin{quote}
        \texttt{let aux = fold\_br [0] (fun x y -> List.map (fun n -> n+1) (x@y))}\\
        \texttt{\phantom{XXXXXXXXXXXXXXXXX}(fun x y -> List.map (fun n -> n-1) (x@y))}
        \end{quote}
        \begin{itemize}
            \item Donner la valeur de l'appel \texttt{aux (B (R (Nil, Nil), B (Nil, Nil)))}.
            \item Redéfinir la fonction du point 3 en utilisant \texttt{aux}.
        \end{itemize}
    \end{enumerate}
}

\exercise{2}{Files de priorité sous forme d'arbres binaires}{
    Une \textit{file de priorité} est une file où chaque élément est associé à une priorité (un nombre, un ordre, un poids, etc.). Dans une file, les éléments sortent dans l'ordre de leur arrivée (FIFO : \textit{First In, First Out}). Dans une file de priorité, les éléments sortent \textbf{selon leur priorité} :
    \begin{itemize}
        \item l'élément avec la priorité la plus basse (ou la plus haute, selon la convention adoptée) est retiré en premier,
        \item l'ordre de retrait n'est donc pas nécessairement l'ordre d'arrivée.
    \end{itemize}
    Nous allons utiliser la convention suivante : l'élément de la file ayant la \textit{priorité minimale} est prioritaire. Le but de cet exercice est d'implémenter les files de priorité en utilisant des arbres binaires. On considère le type :

    \begin{quote}
    \texttt{type ('a, 'p) tree =}\\
    \texttt{| Empty}\\
    \texttt{| Node of ('a * 'p) * ('a, 'p) tree * ('a, 'p) tree}
    \end{quote}

    où \texttt{'a} est le type des éléments de la file et \texttt{'p} le type des priorités.\\
    Une valeur \texttt{t} de type \texttt{('a, 'p) tree} est dite \textit{bien formée} si, \textbf{pour tout sous-arbre de \texttt{t} de la forme \texttt{Node ((x,p), g, d)}, la priorité \texttt{p} est minimale parmi toutes les priorités présentes dans les sous-arbres \texttt{g} et \texttt{d}.} En particulier, la racine d'un arbre bien formé possède toujours la priorité minimale de l'arbre.\\
    Dans la suite de l'exercice, une file de priorité sera une valeur bien formée de type \texttt{('a, 'p) tree}.

    \begin{enumerate}
        \item Expliquer en quoi la structure \texttt{('a, 'p) tree} peut représenter une file de priorité.
        \item Écrire une fonction \texttt{is\_empty} de type \texttt{('a, 'p) tree -> bool} qui teste si une file de priorité est vide. Par exemple :
        \[
        \texttt{is\_empty (Node ((1,0), Empty, Empty)) = false}
        \]
        \item Écrire une fonction \texttt{push} de type \texttt{('a * 'p) -> ('a, 'p) tree -> ('a, 'p) tree} qui insère un couple dans une file de priorité. L'arbre renvoyé par \texttt{push} doit être bien formé.
        \item Écrire une fonction \texttt{peek} de type \texttt{('a, 'p) tree -> 'a} qui retourne l'élément le plus prioritaire de la file sans le retirer. Si la file est vide, la fonction arrête le calcul par \texttt{failwith "File vide"}.
        \item Écrire une fonction \texttt{pop} de type \texttt{('a, 'p) tree -> ('a, 'p) tree} qui prend en argument une file \texttt{t}, retire son élément prioritaire et reconstruit un arbre bien formé à partir des deux sous-arbres de \texttt{t}. À nouveau, si la file est vide, la fonction arrête le calcul par \texttt{failwith "File vide"}.
    \end{enumerate}
}

\exercise{1}{Single Target Shortest Path}{
    On est donné un graphe $G(V, E)$ orienté et pondéré sur les arcs, où les poids sont une fonction $w : E \to \mathbb{N}$ (i.e. tous les poids sont positifs). Le graphe nous est donné en forme de listes d'adjacences. Soit $t \in V$ un sommet du graphe. Trouver un algorithme pour calculer, pour tout sommet $v \in V$, les distances $d(v,t)$. La sortie de votre algorithme doit être un tableau de taille $|V|$ où la case qui correspond au sommet $v \in V$ contiendra la longueur d'un plus court chemin de $v$ à $t$. Quelle est la complexité de votre algorithme ?
}

\exercise{2}{Multiple Sources Shortest Path}{
    On est donné un graphe $G(V, E)$ non-orienté et non-pondéré. Le graphe nous est donné en forme de listes d'adjacences. Soit $s_1, s_2, \dots, s_k \in V$ $k$ sommets du graphe (où $k \le |V|$). Trouver un algorithme pour calculer, pour tout sommet $v \in V$, la quantité $\delta_v = \min\{d(s_1, v), d(s_2, v), \dots, d(s_k, v)\}$, où $d(s_i, v)$ est la distance entre $s_i$ et $v$. La sortie de votre algorithme doit être un tableau de taille $|V|$ où la case qui correspond au sommet $v \in V$ contiendra la quantité $\delta_v$. Quelle est la complexité de votre algorithme ? Trouver un algorithme linéaire dont la complexité ne dépend pas de $k$ pour obtenir tous les points.
}

\exercise{1}{Calculs de mesures et mesure de probabilité}{
    Soit $\alpha > 0$ et $\mu$ la mesure sur $(\mathbb{R}, \mathcal{B}(\mathbb{R}))$ telle que pour tous $a < b$ réels :
    \[
    \mu((a,b)) = \alpha \int_a^b \exp(-|x|) \, \mathrm{d}x.
    \]
    \begin{enumerate}
        \item Calculer $\mu((0,1))$ et $\mu((-1,1))$ en fonction de $\alpha$.
        \item Montrer que $\mu((-\infty, 0)) = \frac{\alpha}{2}$.
        \item Calculer $\alpha$ pour que $\mu$ soit une mesure de probabilité.
        \item Montrer que
        \[
        \mu\left(\left(x_0 - \frac{1}{n}, x_0 + \frac{1}{n}\right)\right) \le \frac{2\alpha}{n}.
        \]
        En déduire $\mu(\{x_0\})$.
    \end{enumerate}
}

\exercise{2}{Nature de différentes applications mesurables}{
    On liste ci-dessous des applications $\mu : \mathcal{B}(\mathbb{R}) \to \mathbb{R}_+ \cup \{+\infty\}$, en exprimant $\mu(A)$, $A \in \mathcal{B}(\mathbb{R})$. Déterminer lesquelles sont des mesures positives et/ou des mesures de probabilité sur $(\mathbb{R}, \mathcal{B}(\mathbb{R}))$. On justifiera la réponse.
    \begin{enumerate}
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \sum_{k=-5}^5 k \indic{\{k \in A\}}$.
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \sum_{k \ge 0} 2^{-k} \indic{\{k \in A\}}$.
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \sum_{k \ge 1} 2^{-k} \indic{\{4-k \in A\}}$.
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \frac{8}{15} + \frac{4}{15} \sum_{k \ge 1} \frac{(\ln(3))^k}{k!} \indic{\{k \in A\}}$.
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \frac{8}{15} \indic{\{0 \in A\}} + \frac{4}{15} \sum_{k \ge 1} \frac{(\ln(3))^k}{k!} \indic{\{k \in A\}}$.
        \item Pour tout $A \in \mathcal{B}(\mathbb{R})$, $\mu(A) = \sum_{x \in \mathbb{Q}} \indic{\{x \in A\}}$.
    \end{enumerate}
}

\exercise{3}{Règle de succession de Laplace}{
    Une boîte contient $k+1$ pièces numérotées de $0$ à $k$. Lorsque la $i$-ième pièce est lancée, $0 \le i \le k$, on obtient Pile avec la probabilité $\frac{i}{k}$. On tire au hasard une pièce dans l'urne pour la jeter ensuite un grand nombre de fois et on suppose alors que le choix de la pièce à lancer étant fait, les jets sont indépendants.
    \begin{enumerate}
        \item Quelle est la probabilité conditionnelle $p_{k,n}$ que le $(n+1)$-ième lancer donne Pile sachant que les $n$ premiers l'ont fait ? Quelle est la limite de $p_{k,n}$ quand $k$ tend vers l'infini ?
        \item Sachant que les $n$ premiers lancers ont donné Pile, montrer que la probabilité conditionnelle que les $m$ suivants fassent de même tend, pour $k$ tendant vers l'infini, vers $\frac{n+1}{n+m+1}$.
        \item On suppose que les $n$ premiers jets ont donné $r$ Piles et $n-r$ Faces. Montrer que la probabilité conditionnelle que le $(n+1)$-ième donne Pile tend, pour $k$ tendant vers l'infini, vers $\frac{r+1}{n+2}$.\\
        \textit{Indication :} on pourra utiliser l'identité :
        \[
        \int_0^1 y^n (1-y)^m \, \mathrm{d}y = \frac{n! \, m!}{(n+m+1)!}.
        \]
        \item Quelle est la probabilité que la $i$-ième pièce ait été tirée si les $n$ premiers jets ont donné Pile ?
    \end{enumerate}
}

\exercise{1}{Homotopie et espaces de chemins sur le cercle}{
    L'exercice utilise les notations suivantes :
    \begin{itemize}
        \item $\mathbb{U}$ désigne l'ensemble des nombres complexes de module 1,
        \item $\pi$ désigne l'application $\mathbb{R} \to \mathbb{U}, \; t \mapsto \exp(it)$,
        \item $\mathcal{C}$ désigne l'ensemble $\{g \in \mathcal{C}^0([0, 1], \mathbb{R}) \mid g(0) = 0, \, g(1) \in 2\pi\mathbb{Z}\}$,
        \item $\mathcal{L}$ désigne l'ensemble $\{f \in \mathcal{C}^0([0, 1], \mathbb{U}) \mid f(0) = f(1) = 1\}$,
        \item $\gamma_n$ (où $n \in \mathbb{Z}$) désigne l'application $[0, 1] \to \mathbb{U}, \; t \mapsto \exp(2in\pi t)$,
        \item pour toute application $h$ de $[0, 1] \times [0, 1]$ dans un ensemble $E$, pour tout $s \in [0, 1]$, on note $h(s, -)$ l'application $[0, 1] \to E, \; t \mapsto h(s, t)$.
    \end{itemize}

    \begin{enumerate}
        \item On note $\mathcal{R}$ la relation binaire sur $\mathbb{R}$ définie par
        \[
        (\forall x, y \in \mathbb{R}) \quad x\mathcal{R}y \iff x - y \in 2\pi\mathbb{Z}.
        \]
        Démontrer que $\mathcal{R}$ est une relation d'équivalence et que $\pi$ induit une application bijective de $\mathbb{R}/\mathcal{R}$ sur $\mathbb{U}$.

        \item On note $\equiv$ la relation binaire sur $\mathcal{C}$ telle que, pour toutes $g_0, g_1 \in \mathcal{C}$, on a $g_0 \equiv g_1$ si et seulement si il existe une application continue $h : [0, 1] \times [0, 1] \to \mathbb{R}$ telle que $h(s, -) \in \mathcal{C}$ pour tout $s \in [0, 1]$, et $h(0, -) = g_0$ et $h(1, -) = g_1$.\\
        Démontrer que $\equiv$ est une relation d'équivalence.

        \item On note $\sim$ la relation binaire sur $\mathcal{L}$ telle que, pour toutes $f_0, f_1 \in \mathcal{L}$, on a $f_0 \sim f_1$ si et seulement si il existe une application continue $h : [0, 1] \times [0, 1] \to \mathbb{U}$ telle que $h(s, -) \in \mathcal{L}$ pour tout $s \in [0, 1]$, et $h(0, -) = f_0$ et $h(1, -) = f_1$.\\
        Démontrer que $\sim$ est une relation d'équivalence.

        \item Démontrer que l'application $\mathcal{C} \to \mathcal{L}, \; g \mapsto \pi \circ g$ induit une application de $\mathcal{C}/\equiv$ dans $\mathcal{L}/\sim$.
    \end{enumerate}
}

\subsection{Intégration et probabilités}
\exercise{1}{Contrôle de qualité de grille-pains}{
    Une entreprise produit des grille-pains à la chaîne, 1000 par jour. On suppose que indépendamment, le $i$-ème grille-pain produit est défectueux avec probabilité 0.002. On note $D_i$ l'événement \{ le $i$-ème grille pain est défectueux \}. L'entreprise fait subir des tests de conformité à chaque grille-pain produit (on suppose que ces tests sont également menés de manière indépendante). On note $C_i$ l'événement \{ le $i$-ème grille-pain produit passe le test de conformité \}. On suppose enfin que $\mathbb{P}(C_i \mid D_i) = 0.02$, $\mathbb{P}(C_i \mid D_i^c) = 0.99$. Les grille-pains qui passent le test de conformité sont mis sur le marché, les autres sont détruits.
    \begin{enumerate}
        \item Quelle est la loi de $G$, le nombre de grille-pains non défectueux détruits en une journée ?
        \item Calculer la probabilité que le $i$-ème grille-pain soit défectueux sachant qu'il ne passe pas le test de conformité.
        \item Calculer la probabilité que le $i$-ème grille-pain soit défectueux et, malgré tout, mis sur le marché ?
        \item Quelle est la loi de $D_m$ le nombre de grille-pains défectueux mis sur le marché par l'entreprise sur une période de 10 jours ? Quelle autre loi usuelle me approche raisonnablement la loi de $D_m$ ? En déduire une valeur approchée de la probabilité qu'il y en ait au moins un.
    \end{enumerate}
}

\exercise{2}{Étude d'une famille de fonctions de répartition}{
    Pour un $C > 0$ on considère la fonction
    \[
    F^{(C)}(x) = \begin{cases} 
    1 - \frac{C}{x^6} & \text{si } x \ge 2 \\ 
    0 & \text{sinon.} 
    \end{cases}
    \]
    \begin{enumerate}
        \item Montrer que $F^{(C)}$ est la fonction de répartition d'une variable aléatoire réelle $X^{(C)}$ \underline{si et seulement si} $C \le 64$.\\
        On suppose dans la suite de l'exercice que $C \le 64$.

\exercise{1}{Bulletin de notes et gestion d'absences en OCaml}{
    Dans cet exercice, il est autorisé (mais pas obligatoire) d'utiliser les fonctions du module \texttt{List} de la bibliothèque standard d'OCaml.

    \textbf{Bulletin de notes.} Nous allons représenter un bulletin de notes à l'aide des types OCaml suivants :
    \begin{quote}
    \texttt{type resultat = Note of int | Absence of bool}\\
    \texttt{type bulletin = resultat list}
    \end{quote}
    Ainsi, un résultat pour une épreuve donnée peut être soit une note (qui est un nombre entier), soit une absence qui peut être justifiée (avec la valeur \texttt{true}) ou non-justifiée (avec la valeur \texttt{false}). Un bulletin de notes est une liste de résultats.\\
    Par exemple, la ligne suivante définit une valeur de type \texttt{bulletin} :
    \begin{quote}
    \texttt{let exemple = [Note 8; Absence true; Note 14; Note 16; Absence false; Absence true]}
    \end{quote}

    \begin{enumerate}
        \item Écrire une fonction \texttt{separer : bulletin -> int list * int * int} qui prend en entrée un bulletin, et renvoie un triplet constitué de :
        \begin{itemize}
            \item la liste des notes,
            \item le nombre d'absences justifiées,
            \item le nombre d'absences non-justifiées.
        \end{itemize}
        Ainsi, pour l'exemple donné, on doit avoir \texttt{separer exemple = ([8; 14; 16], 2, 1)}.

        \item Écrire une fonction \texttt{verifier\_notes : bulletin -> bool} qui vérifie que toutes les notes sont comprises entre 0 et 20 (inclus).

        \item Écrire une fonction \texttt{moyenne : bulletin -> float} qui calcule la moyenne du bulletin, en prenant en compte que :
        \begin{itemize}
            \item les absences justifiées sont ignorées,
            \item les absences non-justifiées comptent comme des 0,
            \item et toutes les notes ont le même coefficient.
        \end{itemize}
        Ainsi, pour l'exemple donné, on doit avoir \texttt{moyenne exemple = 9.5}.
    \end{enumerate}

    \bigskip
    \textbf{Généralisation : listes et types sommes.} Le type \texttt{bulletin} des questions précédentes est un exemple de liste hétérogène : elle peut contenir des valeurs qui sont soit des entiers, soit des booléens. On peut généraliser cette idée à l'aide du type somme défini ci-dessous :
    \begin{quote}
    \texttt{type ('a, 'b) sum = Gauche of 'a | Droite of 'b}
    \end{quote}
    Une valeur de type \texttt{('a, 'b) sum} peut être soit de type \texttt{'a}, soit de type \texttt{'b}. Le constructeur (\texttt{Gauche} ou \texttt{Droite}) permet de savoir quel est le type de l'élément. Ainsi, le type \texttt{(int, bool) sum} est isomorphe au type \texttt{resultat} vu précédemment.

    \begin{enumerate}
        \setcounter{enumi}{3}
        \item Écrire une fonction \texttt{convertir : bulletin -> (int, bool) sum list} qui transforme une valeur de type \texttt{bulletin} en une liste de valeurs de type \texttt{(int, bool) sum} contenant les mêmes données.

        \item Écrire une fonction \texttt{filter\_map : ('a -> 'c option) -> ('b -> 'c option) -> ('a, 'b) sum list -> 'c list} telle que \texttt{filter\_map f g l} parcourt la liste \texttt{l}, dont les éléments sont de type \texttt{('a, 'b) sum}, de la manière suivante :
        \begin{itemize}
            \item si un élément est de type \texttt{'a}, on applique la fonction \texttt{f} ;
            \item si un élément est de type \texttt{'b}, on applique la fonction \texttt{g} ;
            \item dans les deux cas, si l'application de la fonction renvoie \texttt{None}, l'élément est ignoré ;
            \item sinon, lorsque l'application de \texttt{f} ou \texttt{g} renvoie \texttt{Some c}, l'élément \texttt{c} est ajouté au résultat.
        \end{itemize}
        Ainsi, le résultat final de \texttt{filter\_map f g l} est une liste de type \texttt{'c list}.\\
        Par exemple, l'appel ci-dessous :
        \begin{quote}
        \texttt{let f n = if n mod 2 = 0 then Some (n / 2) else None in}\\
        \texttt{let g s = Some (String.length s) in}\\
        \texttt{let l = [Gauche 4; Gauche 7; Droite "Hello"; Gauche 24; Droite "World!"] in}\\
        \texttt{filter\_map f g l}
        \end{quote}
        doit renvoyer la liste \texttt{[2; 5; 12; 6]} (où l'élément \texttt{Gauche 7} a été ignoré).

        \item Réécrire la fonction \texttt{moyenne : bulletin -> float} de la question 1.3, sans utiliser la récursivité, en vous servant des fonctions précédentes \texttt{convertir} et \texttt{filter\_map}, de la fonction \texttt{List.length}, et de la fonction \texttt{List.fold\_left (+) 0}.
    \end{enumerate}
}
